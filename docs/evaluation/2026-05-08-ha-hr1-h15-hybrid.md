# HA-HR1 H15 Hybrid Live Evidence

Date: 2026-05-08

This note records the first live H15 hybrid-router measurements for
`qwen3-coder:30b` plus Codex frontier repair.

## Decision

H15 endpoint work should use `frontier-only` as the current full-task baseline,
not local-only or local-first hybrid.

Reason:

- the first run exposed a harness command-wrapping bug, not a model result;
- after the wrapper fix, the local lane reached `qwen3-coder:30b`;
- the local lane then failed from Ollama runtime resource limits, not task logic;
- frontier repair completed the implementation and the private H15 oracle passed.

The successful repair is positive evidence for the hybrid route shape, but the
later frontier-only baseline is stronger for H15 on this machine because it used
one frontier call instead of three frontier calls plus a failed local call.

## H15 Route Decision After Baselines

The current H15 evidence does not support using local-first hybrid as a
cost-reduction route.

Comparison:

| Route                    | Local calls | Frontier calls | Result      | Main issue                     |
| ------------------------ | ----------: | -------------: | ----------- | ------------------------------ |
| `qwen3-coder:30b` hybrid |           1 |              3 | Oracle pass | local resource failure         |
| `devstral-small-2:24b`   |           1 |              0 | Oracle fail | timeout, incomplete validation |
| Codex frontier-only      |           0 |              1 | Oracle pass | none observed in this run      |

Decision: for H15 endpoint work, use frontier-only as the current baseline route.
Hybrid remains useful as an experiment shape, but not as the default H15 route
until a local candidate can either pass local-only or reliably reduce frontier
repair/review work.
